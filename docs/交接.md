# YT 直播錄製工具：交接

最初需求和決定見桌面的 `YT直播錄製工具_交接.md`。這份記錄**目前做到哪裡、還沒做什麼**，使用者實測後的調整也記在這裡。

## 現況（v0.1.0 前）

第一階段（單路錄製 → 分段 → 轉 MXF）已完成並推上 main，**還沒發布安裝檔**，等使用者實測一輪後再調整、發布。

### 已完成
- 貼網址錄串流本身（yt-dlp 取網址 + ffmpeg `-c copy` 切分段 .ts，不重新編碼）。
- 錄製起點：從現在錄／從直播開頭錄（`--live-from-start`）；排程開始時間。
- 沒開播先等（每 30 秒查一次），直播結束自動停止。
- 斷線、串流網址過期、90 秒沒資料：自動重新抓網址接著錄，分段號接續，空檔寫進 `錄製紀錄.txt`。
- 每段錄完排入轉檔佇列 → EBC 規格 MXF（規格集中在 `core/src/spec.rs`）。轉檔中是 `.mxf.part`，轉完才改名。
- 命名：`<存檔路徑>\名稱\名稱_001.mxf`；原始 .ts 在 `名稱\_ts\`；同名再錄接著編號。
- 設定頁：預設存檔路徑、每段長度、預設錄製起點、同時轉檔數、轉完刪 .ts、ffmpeg／yt-dlp 下載、一鍵更新 yt-dlp、程式自動更新。
- 錄製中電腦不睡眠；關閉程式前確認，確定後讓目前那段存好再關。
- 後端已支援多個任務同時跑（畫面也能一次加多個，但還沒針對多路設計）。

### MXF 規格的依據
EBC 轉檔器只有打包好的 exe，沒有原始碼。規格是照它產出檔的 ffprobe 結果（桌面 `EBC轉檔器_MXF規格.txt`）：
MXF OP1a ／ MPEG-2 4:2:2 HL 50 Mb/s，VBV 17825792 ／ 1920×1080 29.97i 上場優先 ／ BT.709 ／ PCM 24-bit 48k × 8 個單聲道軌。
用真的 ffmpeg 轉出來逐項比對，跟 EBC 檔一致（`core/tests/mxf_real_ffmpeg.rs`）。

**推測、待確認的部分：**
- GOP 15、2 張 B 幀（ffprobe 看不出來，照 XDCAM HD422 慣例）。
- 聲音軌：1 左、2 右、3～8 靜音（EBC 檔每軌放什麼看不出來）。

### 已實測
- 東森新聞 24 小時直播：查狀態（中文標題正常）、從現在錄 25 秒切 10 秒一段、送 `q` 停止、第 1 段轉 MXF，都正常（`core/tests/live_record.rs`）。
- 「從直播開頭錄」：影像、聲音各自用 yt-dlp 從頭抓、接進 ffmpeg 都正常；**兩路經本機 TCP 合併的完整流程還沒跑過**。
- 程式可以正常開啟（debug 版）。

### 實測時發現、已處理
- YouTube 直播現在只給影像、聲音分開的 m3u8，沒有影音合一的格式 → 改成兩路一起錄。
- 聲音分段是 AAC 但網址結尾是 `seg.ts`，ffmpeg 7 會拒絕 → 加 `-extension_picky 0`。
- yt-dlp 輸出到管線時用系統編碼（cp950），中文變亂碼 → 加 `--encoding utf-8`。

## 使用者實測後的調整

### 第 1 輪（11/14，debug 版錄約 10 分鐘）
- 流程正常：先產生 .ts，錄滿一段或按停止後轉成 MXF。
- 檔案大小：TS 約 300 MB／10 分鐘，MXF 約 4.5 GB／10 分鐘（約 60 Mb/s，跟 EBC 範例檔 93 秒 697 MB 一致），屬正常。
  → 1 小時 MXF 約 27 GB，「硬碟空間警告」建議提前做。
- 已改：停止後還在轉檔時關程式，原本不會提醒、轉檔也會被丟下（Windows 不會連帶結束子程序）。
  現在關閉時會提醒「還有 N 段在轉 MXF」，確定關閉會結束轉檔中的 ffmpeg 並清掉 `.part`。
- [ ] 使用者其他回饋：待補。

## 開發注意
- 本機 Rust 預設是 GNU 工具鏈（缺 dlltool 編不過），要加 `+stable-x86_64-pc-windows-msvc`。
- 需要 ffmpeg／網路的測試標了 `#[ignore]`，跑法見 README。這台的 ffmpeg／yt-dlp 可以借用 `%LOCALAPPDATA%\tw.ebc.keyword-title-tool\tools\`。
- git 身分只設在這個 repo（`git config user.name/user.email`），沒設全域。
